AI 圆桌辩论

让四个大模型互相辩论同一个问题，然后给你一个明确的结论——而不是四份需要你自己去比较的答案。

Claude Gemini ChatGPT DeepSeek
在 GitHub 上查看 English README

它解决什么问题

问一个模型，你得到一个视角。问四个模型，你得到四个视角——然后你要自己判断听谁的。这反而更累了。

这个项目的做法不一样：它让四个模型各自扮演指定立场，针对彼此最有力的论点正面交锋，你只需要在旁边主持。真正的比较由系统完成，不是丢给你。

选择悖论的关键在于「筛选」，而不在于「信息」。让人痛苦的是需要你亲自评估的选项数量，而不是可参考的证据数量。200 款酒的酒单让人崩溃；一位品过全部 200 款、只递给你一杯的侍酒师，则完全相反。选项空间一样，体验截然不同。

这个系统扮演的是侍酒师。

具体靠三个机制：

1. 每轮判定共识程度

模型们是真的达成一致，还是仍在僵持？系统会明确标注：

一致 倾向明显 两派对立 仍有争议

一致就快速拍板，不必再想；有争议才值得你花时间。

2. 指出唯一的关键分歧（Crux）

每轮总结会指出：哪一个子问题一旦解决，整场分歧就结束了。你要判断的东西从「这件事该不该做」缩小到「这一个点我怎么权衡」。而那个点，往往取决于你的风险偏好、时间跨度或只有你知道的信息——模型给不了，也不该假装给得了。

3. 结尾必须表态

收尾时系统必须先给出一句话的明确建议，再附上置信度（高／中／低）和「什么情况会推翻这个判断」。如果问题很接近，它也必须选一边，然后把置信度标低——这比和稀泥有用得多。

下面是一场真实辩论（集中持股 vs 分散持股）的实际输出：

Crux — 深入的个股研究，能否把选中长期赢家的基准概率
提高到足以抵消单一持仓 20% 仓位的尾部风险？

Convergence: contested
Decision — 以分散为默认（30 只那一端）；若要集中，
把 5 只高信心标的作为卫星仓位，上限约占组合 20%。

Confidence: medium — 双方并未收敛，但让步是单向的：
反方直接承认了「可管理性」这一点，而正方始终没有回应
尾部风险和 Bessembinder 的论据。

界面

三步开始

git clone https://github.com/QZXP27/ai-roundtable.git
cd ai-roundtable
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./.venv/bin/python server.py

然后打开 http://localhost:8500，在侧边栏的「账号」面板里连接你要用的模型。至少连两个即可开始——没连上的那位只会显示一条错误提示，不会中断整场辩论。

四个模型，成本如何

模型接入方式费用
ClaudeClaude Code CLI走 Claude Pro/Max 订阅
GeminiAntigravity CLI (agy)走 Google 账号 Gemini 订阅
ChatGPTCodex CLI走 ChatGPT 账号（免费档也能用）
DeepSeekAPI 密钥按量计费，一整场约几分钱

前三家通过官方命令行工具运行，用的是你已经付过钱的订阅，不额外花钱、也不需要 API 密钥。DeepSeek 是唯一的例外：它没有订阅制命令行工具，所以走 API——但 deepseek-v4-flash 每百万 token 输入 ¥1 左右、输出 ¥2 左右，跑完一整场辩论也就几分钱。

特意加入 DeepSeek 的理由不只是便宜：它不是西方实验室训练的模型。Claude、Gemini、GPT 的训练语料和对齐方式高度相似，它们意见一致时，这个「一致」可能只是共享了同一个盲区。加一个训练分布明显不同的模型，共识才更有含金量，分歧也更可能是真信号。

常见问题

需要 API 密钥吗？

前三个模型不需要——它们走各自命令行工具已经登录的订阅身份。只有 DeepSeek 需要一个 API 密钥，而且它是可选的：不配也能正常用其余三个。

我的对话内容会上传到哪里吗？

不会。服务只监听 127.0.0.1（本机），所有记录以 JSON 保存在本地 transcripts/ 目录，该目录已被 gitignore。内容只会发给你自己连接的那几个模型供应商。

必须是 macOS 吗？

不必。核心功能在任何能跑 Python 的系统上都可用。只有两项会降级：PDF 导出的中文字体（默认读取 macOS 的 STHeiti，缺失时中文无法渲染，改一下字体常量即可）和 PDF 参考资料上传（依赖 pdftotext）。

可以只用两个模型吗？三个以上呢？

都可以。最少两位参与者，上限没有限制，甚至可以让同一个模型扮演两个不同立场。

我改的提示词和角色设定会被提交到 git 吗？

不会。你保存的角色阵容写入 personas.local.json，自定义提示词写入 prompts.local.json，两者都已 gitignore。仓库里只有通用的默认配置，所以你的个人设置既不会被误传，也不会在 git pull 时被覆盖。
